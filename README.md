# FBI-NEXUS

**Network for Enforcement, X-Intelligence, & Unified Security**

نظام إدارة قضايا فيدرالي كامل (بيئة GTA RP / مكتب لوس سانتوس الميداني) بواجهة عربية RTL وهوية مؤسسية.
يعمل بوضعين:

| الوضع | التخزين | المشاركة بين المستخدمين |
| --- | --- | --- |
| **مشترك (PostgreSQL)** | قاعدة PostgreSQL عبر خادم Express | ✅ كل الحسابات ترى نفس البيانات والملفات |
| **محلي (احتياطي)** | `localStorage` + `IndexedDB` في المتصفح | ❌ كل جهاز مستقل |

الواجهة تكتشف الخادم تلقائيًا عند الإقلاع: إن توفّر `/api/health` عملت بالوضع المشترك، وإلا رجعت للوضع المحلي (لذلك تبقى نسخة GitHub Pages صالحة للاستخدام المحلي).

---

## المزايا

- **الشبكات والهياكل التنظيمية**: إضافة شبكات/عصابات بمواقعها وأعضائها بلا حد.
- **المطلوبون والسجلات**: صور، أدلة، اتهامات، مكافآت، ربط بالشبكات، ونشرة مطلوب PDF.
- **خريطة تفاعلية**: خريطتا لوس سانتوس وسان أندرياس مع حفظ إحداثيات المواقع والعلامات.
- **المذكرات والطلبات القضائية**: توقيع وختم صاحب الحساب، مرفقات PDF/صور، وطباعة جاهزة للاعتماد.
- **البرقيات والتعميمات**: أولويات (عادي/هام/عاجل/سري للغاية) وطباعة رسمية.
- **ملفات القضايا**: مراحل، خط زمني، أدلة، إحالة إلى وزارة العدل، واعتماد/رفض.
- **الأدلة الجنائية**: ترقيم تلقائي، سلسلة حفظ، مختبر ونتائج، ملصقات باركود، وتقارير PDF متعددة الصفحات.
- **بوابة وزارة العدل**: حسابات مخصّصة ترى المذكرات والقضايا المحالة فقط، تعتمد أو ترفض أو ترسل ملاحظات.
- **حسابات وصلاحيات**: كلمات مرور مشفّرة (SHA-256 + Salt)، جلسة موقّعة على الخادم، قفل تلقائي بعد 15 دقيقة.
- **سجل تدقيق** لكل حركة، وتصدير/استيراد الأرشيف كاملًا (JSON).

## النشر على Render (قاعدة بيانات مشتركة)

### 1) إنشاء الخدمة والقاعدة

1. أنشئ حسابًا على [render.com](https://render.com) واربط مستودع GitHub.
2. من لوحة Render: **New → Blueprint** واختر هذا المستودع (ملف `render.yaml` جاهز)، أو أنشئ يدويًا:
   - **New → PostgreSQL**: الخطة Free، الاسم `fbi-nexus-db`.
   - **New → Web Service**: المستودع، Runtime: Node،
     Build: `npm install`، Start: `npm start`.
3. أضف متغيّرات البيئة على خدمة الويب:
   - `DATABASE_URL` = **External Database URL** من صفحة قاعدة البيانات.
   - `SESSION_SECRET` = سلسلة عشوائية طويلة (أو اتركها لـBlueprint لتوليدها).
4. بعد أول نشر، افتح رابط الخدمة `https://<name>.onrender.com` — أول زيارة تزرع الأرشيف والحسابات الافتراضية في قاعدة البيانات.

> **مهم:** خطة Render المجانية لقاعدة البيانات تنتهي بعد **30 يومًا من إنشائها** (مع مهلة 14 يومًا قبل الحذف)، وخدمة الويب المجانية تنام بعد 15 دقيقة خمول وتستيقظ خلال دقيقة تقريبًا. للإنتاج المستمر استخدم خطة مدفوعة أو مزوّد PostgreSQL مجاني دائم مثل Neon/Supabase — الكود يعمل مع أي مزوّد لأنه يعتمد `DATABASE_URL` فقط.

### 2) تحديث الخادم

Render ينشر تلقائيًا عند كل `git push` إلى `main`. لا حاجة لأي خطوة إضافية.

## التشغيل المحلي

### مع PostgreSQL (اختبار الوضع المشترك)

```bash
npm install
npm run pg          # يشغّل PostgreSQL مدمجًا على المنفذ 54329 (بيانات في .pgdata/)
# في نافذة أخرى:
cp .env.example .env   # واضبط DATABASE_URL و SESSION_SECRET
npm start              # http://localhost:3000
```

`npm run pg` يستخدم حزمة `embedded-postgres` للتطوير فقط، وينشئ قاعدة `fib140` بترميز UTF8.

### بدون قاعدة بيانات (الوضع المحلي)

```bash
npm install
npm start          # يعمل لكن يعلن "mode: local" ويستخدم تخزين المتصفح
```

- أو على ويندوز بدون Node: `start.bat` / `tools/serve.ps1`.
- أو أي خادم ملفات ثابت: `npx serve public`.
- GitHub Pages: الوركفلو `.github/workflows/deploy-pages.yml` ينشر `public` تلقائيًا ويعمل بالوضع المحلي.

> لا تفتح `public/index.html` عبر `file://` — التخزين المحلي وWebCrypto يحتاجان `http://localhost` أو HTTPS.

## الحسابات

- تُزرع الحسابات الافتراضية في أول تشغيل (محليًا أو في قاعدة البيانات).
- **A-140** حساب مسؤول كامل الصلاحيات، ومن **الإعدادات** يضيف بقية الحسابات (محققين أو وزارة العدل).
- كل حساب له اسم معروض ورتبة وتوقيع وختم خاص.
- في الوضع المشترك تتحقق كلمات المرور على الخادم وتُصدر جلسة في كوكي `HttpOnly` موقّعة بـ`SESSION_SECRET`، ولا تُرسل كلمة المرور إلى أي طرف ثالث.

## كيف تعمل المزامنة

- الحالة الكاملة للنظام تُخزَّن في جدول `app_state` كـ`jsonb` مع رقم إصدار `rev`.
- كل حفظ من الواجهة يرسل `PUT /api/state` مع الإصدار الذي بدأ منه العميل؛ إن كان هناك تعديل أحدث يرجع الخادم `409` فتعيد الواجهة تحميل أحدث نسخة (بدل الكتابة فوقها بصمت).
- الواجهة تفحص الخادم كل 20 ثانية وتحمّل التحديثات الجديدة تلقائيًا عند عدم وجود نافذة مفتوحة.
- الملفات (صور الأدلة، التواقيع، المرفقات) تُخزَّن في جدول `app_files` وتُحمَّل إلى الواجهة بعد تسجيل الدخول.

**حدود معروفة:** المزامنة على مستوى المستند الكامل، لذا تعديلان متزامنان على نفس اللحظة قد يُسقطان أحدهما (تظهر رسالة تحديث). مناسب لفريق صغير؛ التوسّع الكبير يحتاج جداول مفصّلة لكل كيان.

### واجهة الـAPI

| المسار | الوصف |
| --- | --- |
| `GET /api/health` | حالة الخادم والقاعدة والإصدار الحالي |
| `GET /api/accounts` | أسماء الحسابات (لشاشة الدخول) |
| `POST /api/bootstrap` | زرع الحالة الأولى (مرة واحدة فقط) |
| `POST /api/login` / `POST /api/logout` | إنشاء/إنهاء الجلسة |
| `GET /api/session` | الحساب الحالي |
| `GET/PUT /api/state` | قراءة/كتابة الحالة المشتركة مع تحقق الإصدار |
| `GET/PUT/DELETE /api/files` | ملفات الأدلة والمرفقات |

كل مسارات الحالة والملفات تتطلب جلسة صالحة، وترجع `401` بدونها.

## هيكل المشروع

```
public/
  index.html          # واجهة النظام
  css/main.css        # الثيم والأنماط والطباعة A4
  js/api.js           # عميل الـAPI (وضع مشترك + كشف تلقائي)
  js/db.js            # FileStore — IndexedDB محليًا أو PostgreSQL عبر الخادم
  js/map.js           # الخريطة التفاعلية
  js/auth.js          # الحسابات والصلاحيات والجلسة
  js/core.js          # الحالة، الراوتر، النماذج، لوحة القيادة
  js/ops.js           # المذكرات، البرقيات، القضايا، الأدلة، التقارير، الإعدادات
  assets/             # شعار FBI وخريطتا لوس سانتوس وسان أندرياس
server.js             # Express + PostgreSQL (API + استضافة الواجهة)
render.yaml           # Blueprint لـRender (خدمة + قاعدة بيانات)
tools/
  embedded-pg.mjs     # PostgreSQL محلي للتطوير
  serve.ps1           # خادم ملفات محلي (PowerShell)
  make-map.ps1        # أدوات تجهيز الخرائط
```

## ملاحظات

- المستودع لا يحتوي أي مفاتيح أو أسرار؛ `.env` و`.pgdata/` مستبعدان.
- في الوضع المحلي: مسح بيانات المتصفح يحذف الأرشيف — استخدم **الإعدادات → تصدير الأرشيف الكامل**.
- في الوضع المشترك: خذ نسخة احتياطية من قاعدة البيانات دوريًا (أو صدّر JSON من الإعدادات).
- خطة Render المجانية للقواعد تنتهي بعد 30 يومًا — راجع القسم أعلاه.
